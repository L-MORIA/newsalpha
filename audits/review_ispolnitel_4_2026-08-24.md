# Критический обзор проекта `newsalpha`

**Дата:** 24 августа 2026
**Статус проекта:** VERY EARLY — ~5% реализации

---

## Общая оценка

Проект **newsalpha** — это попытка реализовать метод STTM (Stock Tonal Topic Modeling) для прогнозирования движений акций Мосбиржи на основе анализа новостей. Документация впечатляюще тщательная (4 аналитических отчёта на 700+ строк, 193-строчный план), однако фактическая реализация состоит из **одного модуля на 146 строк** и CLI-обёртки на 78 строк. Все 8 ключевых подмодулей пусты.

## КРИТИЧЕСКИЕ ПРОБЛЕМЫ

### 1. Конвертер для "ria" не реализован
**Файл:** `src/newsalpha/io/fetchers.py:63-93`

Функция `_iter_rows()` обрабатывает только `"interfax"` и `"lenta"`, но не `"ria"`. При этом:
- `scripts/fetch_news.py:23` указывает `--sources lenta,ria` как значение по умолчанию
- `DOWNLOAD_URLS` (строка 21-22) содержит URL для ria
- Результат: архив ria скачивается (~100+ МБ), но конвертация падает с `ValueError`

**Влияние:** Дефолтная команда `python scripts/fetch_news.py` всегда завершается ошибкой для ria.

---

### 2. Ложные ошибки при пропуске источников
**Файл:** `scripts/fetch_news.py:41-45`

Если `name == "kommersant"` (или другой источник без `DOWNLOAD_URLS`), код:
1. Печатает предупреждение
2. Добавляет `name` в список `failures`
3. Завершается с `sys.exit(1)`

**Влияние:** `python scripts/fetch_news.py --sources kommersant` завершается с ошибкой, хотя пропуск — ожидаемое поведение.

---

### 3. Нет retry-логики для сетевых запросов
**Файл:** `src/newsalpha/io/fetchers.py:33`

`requests.get(url, stream=True, timeout=60)` — одна попытка. Для архивов ~170 МБ любой сетевой сбой = полная ошибка.

**Влияние:** Хрупкая загрузка данных, особенно на ненадёжных соединениях.

---

### 4. Нет проверки целостности скачанных данных
**Файл:** `src/newsalpha/io/fetchers.py:25-42`

Архивы скачиваются и сохраняются без проверки хешей (SHA256/MD5). Повреждённые или подменённые данные будут тихо использованы в пайплайне.

## АРХИТЕКТУРНЫЕ ПРОБЛЕМЫ

### 5. README ссылается на 5 несуществующих скриптов
**Файл:** `README.md:25-31`

README описывает: `preprocess.py`, `train_topics.py`, `build_index.py`, `backtest.py`, `run_all.py`. **Ни один из них не существует.** Существует только `fetch_news.py`.

**Влияние:** Любой, кто следует quick-start, сразу получит `FileNotFoundError`.

---

### 6. Все 8 подмодулей — пустые заглушки
**Файлы:** Все `__init__.py` в `src/newsalpha/` кроме `io/`

Модули `text/`, `topics/`, `sttm/`, `baselines/`, `evaluation/`, `strategy/`, `viz/` содержат только пустые `__init__.py`. Нулевой код.

**Влияние:** Ядро STTM, все бейзлайны, вся оценка, вся логика стратегии — ничего не реализовано.

---

### 7. Нет ни одного теста
**Директория:** `tests/` пуста

`pyproject.toml:42-43` настраивает pytest, но тестов нет. План обещает "каждую формулу ядра STTM" в тестах.

**Влияние:** Нулевое покрытие тестами. Единственный модуль с кодом (`fetchers.py`) не протестирован.

---

### 8. Раздельное управление зависимостями
**Файлы:** `pyproject.toml` vs `requirements.txt`

- `requirements.txt` содержит: selenium, undetected-chromedriver, jupyterlab, tqdm, ruff, pytest, pytest-xdist
- `pyproject.toml` не содержит этих зависимостей
- `pip install -e .` не установит критические инструменты разработки

**Влияние:** Разработчики, использующие только `pip install -e .`, будут иметь неполную среду.

## ПРОБЛЕМЫ КОДЕСТИЛЯ

### 9. Небезопасное открытие файла
**Файл:** `scripts/fetch_news.py:31`

```python
cfg = yaml.safe_load(open(args.config, encoding="utf-8"))
```

Открытие файла без `with`-контекста — утечка ресурсов. Будет ругаться под `tracemalloc`.

---

### 10. sys.path как хак для обнаружения пакета
**Файл:** `scripts/fetch_news.py:14-15`

```python
sys.path.insert(0, str(ROOT / "src"))
```

Это маскирует проблемы с упаковкой пакета. Если пакет установлен через `pip install -e .`, это не нужно.

---

### 11. Мёртвый код: interfax
**Файл:** `src/newsalpha/io/fetchers.py:67-75`

Ветка `interfax` в `_iter_rows()` обращается к `corus.load_ods_interfax`, который требует удалённый датасет ODS. Код никогда не будет выполнен на практике.

---

### 12. Нет валидации параметра date_range
**Файл:** `src/newsalpha/io/fetchers.py:111`

```python
lo, hi = pd.Timestamp(date_range[0]), pd.Timestamp(date_range[1])
```

Некорректные строки дат из конфига дадут непонятную ошибку `TypeError`/`ValueError`.

---

### 13. Хрупкое сравнение рубрик
**Файл:** `src/newsalpha/io/fetchers.py:112,137`

Фильтр рубрик использует точное вхождение. Рубрика типа `"экономика;бизнес"` **не совпадёт** с `"экономика"`, хотя содержит его.

---

### 14. Большое потребление памяти
**Файл:** `src/newsalpha/io/fetchers.py:103,142`

`batch_size=200_000` — до 200k словарей в памяти перед записью в parquet. Тексты новостей могут быть по several КБ. Для корпуса Lenta (739k строк) — несколько ГБ RAM.

## ВЫВОД

Проект находится на **очень ранней стадии планирования/скаффолдинга**. Документация исключительно тщательная (4 аналитических отчёта на 700+ строк, 193-строчный план, 20-пунктная критика метода). Однако фактическая реализация — это **один 146-строчный модуль** с несколькими корректностными проблемами и CLI-обёртка. Все 8 ключевых подмодулей пусты. README рекламирует 5-шаговый пайплайн, где 4 из 5 скриптов не существуют.

**Приоритеты для исправления:**
1. Реализовать конвертер ria или убрать из дефолта
2. Исправить обработку пропуска источников (не добавлять в failures)
3. Добавить retry-логику для скачивания
4. Удалить мёртвый код interfax
5. Добавить хотя бы базовые тесты для fetchers.py
6. Привести README в соответствие с реальным состоянием
