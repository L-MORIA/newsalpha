# Обзор клонов и похожих проектов (GitHub, проверено 24.08.2026)

Контекст: мы реализуем метод **STTM** (PeerJ CS 2022, doi:10.7717/peerj-cs.1156) — прогноз
направления движения акций из новостного потока через тематическое моделирование.
Задача обзора: найти клоны оригинального репозитория `hse-scila/-STTM` и проекты,
похожие по смыслу (текст новостей → сигнал для акций), разобрать каждый и вывести
следствия для нашего проекта `newsalpha`.

Прямых полных клонов STTM нет. Все живые производные образуют одну линию:
`hse-scila/-STTM` → `marin-shartey/sttm` (чистка) → `isomiki/sttm-trader` (бэктест).
Русскоязычных аналогов не существует вообще.

## 1. marin-shartey/sttm — «чистый STTM»

**Метаданные:** создан 30.06.2025, последний push 21.07.2025; Python; 0 звёзд, 0 форков,
лицензии нет; коммится вместе с `.idea` (PyCharm).

### Что внутри
```
core/
├── config.py                      # вся конфигурация в одном месте
├── lib/news_preprocessing.py      # препроцессинг текста
├── run_news_preprocessing.py      # шаг 1: сырые новости → data/preprocessed_news/
├── run_lda_modeling.py            # шаг 2: LDA → data/models/, недельные BoW
├── run_sttm_lda_computation.py    # шаг 3: STTM-индекс → data/sttm_indices/
└── run_simulation.py              # заготовка симуляции
data/sample/news/{kommersant,ria,vedomosti}_sample.csv   # сэмплы авторов (те же!)
data/sample/time_series/shares_TQBR_*.csv                # те же CSV MOEX, что у нас
```

### Конфигурация (`core/config.py`)
- `NewsPublisher`: enum `KOMMERSANT` / `RIA_NOVOSTI`;
- `TRAINING_YEARS = [2021, 2022, 2023]`, тестовый год автоматом следующий;
- `TICKER = "MOEX"` — **только индекс**, не отдельные акции;
- лемматизация — **MyStem** (бинарник кладётся в `core/lib/mystem`);
- рыночные данные — **.xlsx** (не исходные CSV авторов).

### Как считает индекс (`run_sttm_lda_computation.py`)
```python
topic_matrix, returns, aligned_index = align_weekly_topics_and_returns(...)
correlations = compute_topic_return_correlations(topic_matrix, returns)
sttm_index = topic_matrix @ correlations
```
То есть **каждый тематический поток напрямую коррелирует с дох. индекса** и взвешенная
сумма даёт индекс. Это *упрощение относительно статьи*: в оригинале значимость считается
на уровне слов (корреляция потока слова с рядом цены), тональность темы — взвешенная
сумма значимостей её слов (см. патент EA04248B1, п. 4–5). Прямая корреляция тем с
доходностью теряет пословную интерпретируемость и устойчивость при малых данных.

### Чего не доделано (видно по TODO)
- `TODO: build STTM indices for all market data, pick top 20% according to granger test`
  — нет ни перебора акций, ни теста Грейнджера, ни отбора топ-20%;
- нет базлайнов, нет DTM, нет торговой стратегии;
- README честно называет проект «кодом к статье», но воспроизводит лишь каркас.

### Вердикт
Полезен как **образец структуры модулей** (последовательность из трёх запускаемых
шагов, конфиг отдельным файлом) и как подтверждение стека препроцессинга (MyStem).
Методически слабее статьи: упрощённый индекс, один тикер, без валидации.
Скопировать у нас: схему `run_*`-скриптов и разделение config/lib. Не копировать:
упрощённую формулу индекса.

## 2. isomiki/sttm-trader — «STTM-трейдер» (главный референс)

> ⚠️ **ВАЖНЫЙ ВЫВОД: это проект про ТОТ ЖЕ рынок, что и наш.** Не расширение на новую
> нишу, а та же связка «российские акции MOEX (TQBR) + Коммерсантъ»: тикеры
> `shares_TQBR_*`, обучение 2013–2023, out-of-sample тест отдельным годом.
> То есть **isomiki/sttm-trader — самый продвинутый проект в мире по нашей теме
> и прямой конкурент-ориентир в той же нише** (при этом полного корпуса данных,
> теста Грейнджера и базлайнов у него нет — см. ниже).

**Метаданные:** создан и запушен 15.04.2026 (совсем свежий); Python 3.9; 0 звёзд;
лицензии нет. По дереву файлов и сэмплам видно: **вырос из рефакторинга
marin-shartey/sttm** (та же структура `core/`, те же `.idea`, те же сэмплы),
поверх которого автор построил собственный торговый контур.

### Что добавлено к рефакторингу
```
core/lib/sttm_lda.py        # тональности тем, тонический тематический поток
core/lib/market_data.py     # загрузка котировок, недельные доходности
core/lib/granger_test.py    # тест Грейнджера (перенесён из оригинала)
core/lib/results.py         # статистика результатов
core/run_sttm_training.py   # обучение тональностей по каждой акции
core/run_backtest.py        # бэктест на отдельном тестовом году
core/run_results_calc.py    # агрегация: недельные/годовые доходности, z-score, p-value
core/lib/unused/            # старые модули оригинала отложены (sestm, embeddings, ...)
```

### Методика (из `config.py` и `run_backtest.py`)
- Обучение: Коммерсантъ, **2013–2023** (настраивается), например train 2016–2020,
  тест 2021 — честное разбиение по годам;
- данные новостей: txt-файлы по дням `data/raw/news/kommersant/YYYY-MM-DD/NNNN__дата.txt`;
- лемматизация MyStem;
- **по каждой акции отдельно**: тональности тем + сигмоидная калибровка
  `(a, b)` отображения STTM-индекса в вероятность роста:
  `predicted_probs = expit(a * signal + b)` (логистическая регрессия сигнал→знак
  доходности на train);
- тестовые документы **фильтруются по словарю обученного периода**
  (`[t for t in tokens if t in trained_dictionary.token2id]`) — правильная гигиена
  против утечки данных;
- недели в ISO-календаре (`iso_year, iso_week`), сигнал сравнивается с доходностью
  следующей недели;
- параллельная загрузка (asyncio + ThreadPoolExecutor), логирование в `logs/`.

### Опыт автора (из README, дословно)
> «In my experience it's very noisy, but there are some promising results when using
> Kommersant news and data before 2022 (Russo-Ukrainian war).»

Это независимое подтверждение двух наших положений: (а) сигнал шумный, нужны
статистические тесты, а не одна кривая капитала; (б) режим рынка после 02.2022
ломает закономерности до 2022 — совпадает с нашим планом out-of-sample 2022–2026
как отдельным стресс-тестом.

### Вердикт
**Самая полная публичная реализация STTM в мире** и ближайший ориентир. Взять:
ISO-недельный календарь, фильтрацию словаря на тесте, сигмоидную калибровку сигнала,
разделение train/test по годам, идею логирования прогонов. Отличаться: у него нет
теста Грейнджера в пайплайне оценки, нет базлайнов, нет сравнения со статьёй,
лицензии нет; данные у автора свои («can be found online or by contacting me») —
полного корпуса он тоже не публикует.

## 4. Реплики SESTM (Ke/Kelly/Xiu «Predicting Returns with Text Data»)

SESTM — англоязычный первоисточник подхода «слова→тоналность→портфель», именно его
авторы STTM берут главным базлайном. Официального кода у статьи нет, есть любительские реплики:

### 4.1 mannymistry/predictreturnswithtext (R)
- Создан 13.05.2020, заброшен после 29.05.2020; оформлен как R-пакет (DESCRIPTION/NAMESPACE);
- данные: цены Tiingo (RDS), новости VCorpus, конституенты S&P500;
- README: «replicate the key findings… still in heavy development» — развитие не продолжилось.
- Ценность: пошаговая демонстрация алгоритма SESTM (скрининг слов по частоте,
  тональность через супер-/подвыборки, ранжирование портфеля), но язык R и рынок США.

### 4.2 yw562/predicting-returns-with-text-data-old (Python) — самая полезная реплика
- Создан 03.06.2025, push 08.06.2025; заявлена связь со статьёй на воркшоп ICML
  (автор представляется аффилированным с Кембриджем);
- файлы: `day2_sestm_pipeline.py` + варианты `_delete_noise`, `_delete_rtamp`,
  `_delete_noise(rtamp)` — **эксперименты по фильтрации шума** в тональностях;
  `Day3BacktestPipelinenew.py` — бэктест; `grid_results/grid_summary.html` — сеточный
  подбор гиперпараметров; артефакты: `tone_distribution.png`, облака слов тем,
  JSON-словари тем;
- открытые данные (`reduced_dataset-release.csv`).
- Ценность: свежий Python-референс для нашего этапа 5 (базлайн SESTM), включая
  приёмы шумоподавления и grid search. Название «old» намекает на планируемую
  новую версию репозитория.

### 4.3 PKUwangchen/Text-Data-predict-returns (Python)
- 08–10.2023; `bert.py`, `fine_tune*.py`, `zero-shot.py`, `five-shot.py`,
  `minute_level.py` — это **не SESTM**, а fine-tune/zero-shot BERT для предсказания
  доходностей, включая минутные данные. README пустой. Показывает альтернативное
  направление (LLM вместо тематических моделей), кодовой ценности почти нет.

### 4.4 FaisalQarah/SESTM-Tadawul-Sentiment-and-Emotion-Analysis
- 01.10.2024; ноутбуки сентимент/эмоций по датасету форума саудовской биржи Tadawul,
  матрицы ошибок. SESTM в содержании фактически отсутствует — имя в названии вводит
  в заблуждение. Ценность: датасет Tadawul, если когда-нибудь понадобится
  незападный пример.

### 4.5 DylanWhitmire/Earning-calls-sentiment
- Создан 21.05.2026, активен (push 15.06.2026); учебный проект под руководством
  преподавателя: PEAD (post-earnings announcement drift) на изменениях сентимента
  транскриптов коллов; сравнение LM-словаря, FinBERT, **SESTM** и LLM.
- Пока только hello-world ноутбуки (`SESTM_Hello_World.ipynb`). Полезен как сигнал,
  что SESTM жив в актуальных исследованиях 2026 года; следить, не появится ли
  рабочая реализация.

## Выводы для newsalpha

> ⚠️ **Ключевой вывод обзора:** самый продвинутый публичный проект (isomiki/sttm-trader)
> работает на **том же рынке, что и мы** — российские акции MOEX TQBR + новости
> Коммерсанта. Конкурентов/референсов в другой рыночной нише нет; всё живое
> сосредоточено ровно в нашей задаче. Это одновременно и валидация темы (независимый
> разработчик довёл метод до торговли на наших данных), и ориентир по качеству,
> который нужно превзойти: у него нет Грейнджера в пайплайне, базлайнов, сравнения
> со статьёй и публикуемых данных.

1. **Ниша свободна.** За 4 года после публикации: 2 форка (один осмысленный),
   1 активное расширение, 0 русскоязычных проектов, полного воспроизведения
   методики статьи (слова→тональность тем, Грейнджер по каждой акции, 26 базлайнов,
   long-only стратегия) не сделал никто.
2. **Линейка кода одна** — всё живое происходит от оригинала; наши отличия надо
   строить на: верности методу (не упрощать индекс как marin-shartey), полной
   оценке (Грейнджер + эконометрика как isomiki, но у него этого тоже нет полностью),
   воспроизводимых данных (готовые корпуса + скрапинг Ъ), лицензии и документации.
3. **Практические заимствования:**
   - структура `run_*`-шагов + отдельный `config.py` (оба проекта);
   - MyStem для лемматизации (оба; совпадает с pymystem3 из патента ВТБ);
   - ISO-недели и фильтрация словаря на тесте, сигмоидная калибровка сигнала
     (isomiki);
   - эксперименты с фильтрацией шума тональностей (yw562).
4. **Подтверждённые риски:** сигнал «очень шумный»; режим рынка после 02.2022
   ломает связи — в плане уже есть отдельный out-of-sample тест 2022–2026.
5. **Мониторить:** возможную новую версию yw562 (без «old»), развитие
   DylanWhitmire (SESTM в PEAD), новые форки оригинала.
