## 2. Перевод аннотации (сжато)

«Мы предлагаем новый подход к количественной оценке тональности новостных сообщений. Наша модель — **SSESTM** (Supervised Sentiment Topic Model) — использует доходности акций для обучения тематической модели, которая интерпретирует статьи через призму "бычьих" и "медвежьих" тем. Модель генерирует оценку p-score — вероятностную метрику тональности, которая предсказывает аномальную доходность акции на следующий день. Портфельные стратегии, построенные на p-score, дают Sharpe ≈ 4.3 (equal-weighted). Мы также доказываем теоретические гарантии: состоятельность оценок и способность процедуры отбора слов отделять тональную лексику от нейтральной при росте корпуса».

Ключевая идея одной фразой: **тональность слова определяется не словарём и не разметкой, а тем, как двигались акции в дни публикаций со этим словом.**

## 3. Метод по шагам (как в статье)

### 3.1 Постановка
- Корпус D: статьи d_j, каждая привязана к тикеру и времени публикации.
- Для каждой статьи — нормированная доходность r_j (избыточная относительно рынка/факторов) между публикацией и исполнением.
- Цель: для новой статьи получить p ∈ [0,1] — вероятность того, что она «позитивная», затем агрегировать по акциям в торговый сигнал.

### 3.2 Отбор слов (screening)
1. Статьи делятся на верхнюю и нижнюю половины по r_j (balanced top/bottom).
2. Для слова i: f_i = доля позитивных статей среди статей, где слово встретилось.
3. Фильтр значимости: слово остаётся в словаре, только если оно встречалось минимум в `threshold × log(N_n)` статьях (N_n — суммарное число вхождений всех слов). Это условие из теории — обеспечивает «отделение» тональных слов от шума асимптотически.
4. Из выживших берут K лучших по f_i (bullish) и K худших (bearish) — итоговый словарь ~ несколько сотен слов.

### 3.3 Supervised topic model
- Ровно **две темы**: позитивная O⁺ и негативная O⁻ (в отличие от классического LDA, число тем фиксировано и имеет экономический смысл).
- Каждая статья h_j = распределение над двумя темами; целевая переменная — ранг доходности.
- Оценка — максимизация правдоподобия с **Beta-приором** (штраф λ тянет веса к 0.5, борьба с переобучением); в коде реализовано как взвешенная линейная регрессия с проекцией на симплекс (см. §5).
- P-score новой статьи: p = доля «позитивной темы» в её вектор-представлении.

### 3.4 Торговое правило
- Ежедневно: long top-50 / short bottom-50 акций по среднему p-score их новостей за день.
- Исполнение по цене открытия следующего дня; **статьи, опубликованные 9:00–9:30 ET, исключаются** (нельзя честно отторговать до открытия).
- Мелкие акции отсекаются breakpoint'ом NYSE 20% по капитализации.

### 5.1 Что показал разбор кода (файлы прочитаны)

**Роллинг-схема** (`InSample_Validation_function_1.m`): insample 10 лет → validation 5 лет → OOS год `begin+15`. Гиперпараметры: `lambda` (штраф), `Article` (минимум статей), `pos_word_num`/`neg_word_num`.

**Screening (точный код):**
```matlab
f_i_article = positive_article_count ./ total_article_count;   % доля позитивных статей у слова
WordChoose  = find(total_article_count >= total_article_count_thresh * logNn_year);  % log-N порог
% затем топ-K по f_i → bullish-словарь, дно-K → bearish
```
То есть частота считается на уровне **статей** (сколько статей со словом позитивны), а не вхождений.

**Оценка тем (Method 3):** вместо EM — регрессия на ранговых весах:
```matlab
H = D1 ./ sum(D1,1);                    % нормировка статьи
W1 = rank(Return)/num_articles; W2 = 1-W1;   % ранги доходностей как цели
O = H*W'*inv(W*W');                     % линейная регрессия
O(O<0)=0; O = O./sum(O);                % проекция на симплекс
```

**OOS-скоринг** (`OOS_p_function.m`): новые статьи проецируются на словарь (`D(words_id,:)`), умножаются на O; статьи 9:00–9:30 ET удаляются (`Hour_delete = find(ET_hour>=900 & ET_hour<=930)`); NaN-доходности выбрасываются.

**Портфели** (`Portfolio_EW/VW*.m` — десятки вариантов): top-50/100 EW и VW, NYSE 20%-breakpoint, явный подсчёт `transaction_cost` и `transaction_cost_corrected`, варианты без дней отчётностей, контроль оборота, удержание day −1…+10, intraday 30-мин интервалы, novelty-фильтр повторных новостей.

Вывод: официальный код — это, по сути, **эталонная инфраструктура бэктеста новостной стратегии**, а не просто «моделька». Именно так должен выглядеть наш пайплайн.

## 7. SESTM vs STTM (что взял Рябых)

| Аспект | SESTM (Ke/Kelly/Xiu) | STTM (Рябых, PeerJ 2022) |
|---|---|---|
| Рынок | США (DJN + CRSP) | Россия (MOEX index + Ъ/РИА/Ведомости) |
| Тематическая модель | Supervised, ровно 2 темы | Несупервизированные LDA/DTM + отдельный supervised-слой |
| Словарь тональности | Из доходностей (f_i + log-N порог) | Из доходностей (корреляция потока слова с ценой) — **та же идея** |
| Горизонт | Дневной (исполнение на открытии) | Недельный (ребалансировка раз в неделю) |
| Отбор акций | Top-50 long / bottom-50 short | Top-20% long-only |
| Издержки | Явно в коде, net-SR 1.94 | Не учитывались (замечание оппонентов) |
| Теория | Гарантии состоятельности | Нет |
| Код | MATLAB, официальное приложение | Python, не опубликован полностью |
| Шарп (валовой) | 4.29 EW | 1.37 (лучший вариант, Ъ) |

STTM — это адаптация идеи SESTM: несупервизированная тематическая модель вместо supervised двухтемной, недельный горизонт, российский рынок. Ключевой заимствованный элемент — **supervised-словарь из доходностей**.

## 8. Что переносим в newsalpha

1. **Screening-формула**: f_i на уровне статей + порог `count ≥ thresh·log(N)` — прямая замена нашей корреляции; проверить обе.
2. **Роллинг-схема гиперпараметров** 10+5 лет (у нас масштаб: годы → месяцы, но принцип тот же).
3. **Издержки и оборот** считать с первого дня бэктеста (Portfolio_*_turnover варианты — образец).
4. **Фильтр «неотторгуемых» новостей** (аналог 9:00–9:30 ET: ночные публикации Ъ → исполнение на открытии).
5. **Фильтр микро-капы** (аналог NYSE 20% breakpoint для MOEX TQBR).
6. **Novelty-фильтр** повторных новостей об одном событии.
7. Их `pos_table.csv/neg_table.csv` — справочник при сопоставлении русских эквивалентов.
8. Baseline-дисциплина: всегда сравнивать с простым словарём (LM ↔ наш аналог) — у SESTM словарь почти не проигрывает (4.3 vs 3.2), значит и нам нужен такой тест.
